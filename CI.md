# CI — Flutter runs in the cloud (no local SDK)

`.github/workflows/flutter-ci.yml` is how this app is verified and built.
Flutter runs **entirely on GitHub runners** — `subosito/flutter-action` pulls
the SDK from git, so **no local Flutter install is needed** (same approach as
the `embedded-finance` repo). A local SDK can come later.

On every **push to `main`** it: `flutter create` (generates the native folders)
→ `pub get` → **analyze** → **test** → **build per-ABI debug APKs**, captures
each step's log as a **diagnostics artifact**, and publishes the APKs to a
rolling **`flutter-latest`** Release.

## Use it
- **Push to `main`** → CI runs. Read the **`diagnostics`** artifact
  (`analyze.txt` / `test.txt` / `build.txt`) for the first real `flutter analyze`
  result — that's the truth-check we can't run without the SDK.
- The **download link** is the rolling release:
  `…/releases/tag/flutter-latest`. Most phones grab `app-arm64-v8a-debug.apk`
  (~50MB, per-ABI = smaller than a universal APK).
- **Manual run:** Actions → *Flutter CI* → Run workflow (APKs upload as
  artifacts).

## The gate
The build **fails only on real analyze `error •` lines** (or a missing APK).
Info/warning lints are **non-blocking** — so the rolling APK keeps shipping
while we burn down nits from the diagnostics artifact.

## Notes
- Debug APKs are standalone/installable (Flutter debug ≠ RN debug; no Metro
  server needed).
- iOS builds need macOS runners + Apple signing (the parked membership).
- Platform folders (`/android`, `/ios`, …) are **gitignored** — regenerated by
  `flutter create` in CI (and locally, later).
